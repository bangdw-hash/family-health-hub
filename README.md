# Family Health Hub

기준: 2026-11-03 · 웹앱 v0.5.0 · 진료 전·중·후 관리 + AI(OCR) 예약 안내 읽기

환자 1명을 여러 보호자(가족·요양보호사 등)가 같은 권한 체계에서 함께 관리하는 가족 건강 관리 앱입니다.

## 구성
- React + Vite 반응형 웹앱 (PC/모바일 브라우저), Capacitor 7 기반 Android/iOS 셸
- Supabase Auth · PostgreSQL · RLS · Storage(비공개 버킷) · Realtime
- 마이그레이션: `20261031000000_initial.sql` → `20261101000000_collaboration.sql` → `20261102000000_calendar_feeds.sql` → **`20261103000000_visit_details.sql`(v0.5, 적용 필요)**
- 엣지 함수: `calendar-feed`(캘린더 구독), **`ai-ocr`(AI 읽기, v0.5 신규)** — 둘 다 재배포 필요

| 단계 목록 | 진료 전 준비(금식·지참물·서류·약 조정), 당일 진행(접수·검사·측정·대기·진료·수납), 진료 후 할 일(약국·다음 예약·결과 확인). 완료 체크에 누가·언제 기록 |
| 템플릿 | 채혈 후 진료 / 영상검사 후 진료 / 일반 진료 |
| 진료 상세 화면 | 진료 전·진행·진료 후 탭, 길찾기(네이버·카카오·구글 지도), 다음 예약 만들기, 기록·복약 연결 |
| 병원 정보 저장 | 자주 가는 병원 이름·전화·주소 재사용 |
| AI 읽기(OCR) | 병원 앱 캡처·문자·안내문 사진 → 예약 항목 자동 채움. 검사+외래가 함께 있으면 자동 연결. 읽은 결과는 확인 후에만 저장 |
| AI 설정(관리자) | 더보기 > AI 설정(OCR): 서비스사(Anthropic/OpenAI/Google)·API 키·모델 1회 등록 → 패밀리 전원이 사용. 키는 Supabase Vault 암호화, 구성원에게 노출 없음, 하루 한도, 모델 목록 불러오기·연결 테스트 |
| 캘린더·알림 | 장소·준비사항 포함, 금식 시작은 별도 일정/기기 알림, 의료진·예약번호·전화·수납·안내문 원문은 외부로 내보내지 않음 |

AI 읽기 구조: 앱 → 엣지 함수 `ai-ocr`(로그인·구성원 확인, 하루 한도 검사) → 등록된 AI 서비스. 키는 이 함수만 읽습니다. 사진·글자는 선택한 AI 서비스로 전송되므로 개인정보 동의 문안에 반영했고(동의 버전 `2026-11-03`, 모든 사용자 재동의), 서비스 요금은 키 소유 계정에 청구됩니다. AI를 설정하지 않으면 글자 붙여넣기 규칙 기반 분해만 동작합니다(사진은 읽을 수 없음).

## v0.4.0 외부 서비스 연동
| 기능 | 방식 | 필요한 설정 |
|---|---|---|
| 구글·아이폰 캘린더 구독 | 구성원별 비밀 URL(.ics)을 캘린더가 주기적으로 가져감(진료 일정 + 복약 시간 반복 일정) | 마이그레이션 + 엣지 함수 배포 |
| 일정 추가 | 진료 일정마다 "구글 캘린더에 추가" 링크, .ics 파일 받기 | 없음 |
| 카카오톡 공유 | 카카오 JS SDK `Kakao.Share.sendDefault` (키가 없으면 기기 공유창, 최후에는 클립보드) | `VITE_KAKAO_JS_KEY` |
- 외부로 나가는 내용: 환자 이름, 병원·진료과, 일시, 동행자, (선택) 복약 시간·약 이름. **진단명·증상·검사·메모는 내보내지 않습니다.**
- 구독 URL은 로그인 없이 읽히는 비밀 링크입니다. 앱에서 재발급·해제할 수 있고, 패밀리에서 제거되면 즉시 중단됩니다. 반영 주기는 구글이 정하며 수 시간~하루가 걸릴 수 있습니다.
- 구글 계정 OAuth 직접 동기화, 카카오 알림톡 자동 발송은 구현하지 않았습니다(요청 범위 밖).

## 실행
1. Family Health Hub **전용** Supabase 프로젝트를 사용합니다(다른 서비스 DB에 적용 금지).
2. 마이그레이션 4개를 순서대로 SQL Editor에서 실행합니다(2번째부터 재실행해도 안전). 4번째(`visit_details`)는 Supabase Vault 확장이 필요합니다(대시보드 Database > Extensions > supabase_vault).
   엣지 함수를 배포합니다: `supabase functions deploy calendar-feed --no-verify-jwt` 및 `supabase functions deploy ai-ocr --no-verify-jwt --project-ref <프로젝트 ref>` 또는 `npm run bundle:feed` 로 만든 `deploy/*.single.ts` 를 대시보드 Edge Functions 편집기에 붙여넣고 **Verify JWT를 끕니다**.
   카카오 공유를 쓰려면 카카오 개발자 콘솔의 JavaScript 키를 `VITE_KAKAO_JS_KEY`(GitHub Actions 변수 `FHH_KAKAO_JS_KEY`)로 설정하고 웹 도메인을 등록합니다.
3. `.env.example`을 `.env.local`로 복사하고 URL과 **publishable key**만 입력합니다(service_role 키 금지).
4. `npm install && npm run dev`, 배포 전 `npm run build`.
5. Supabase Auth의 Site URL·Redirect URL을 실제 배포 주소로 설정합니다.

서버가 아직 구버전이면 앱이 "서버 업데이트가 필요합니다" 안내 화면을 표시합니다.

## 테스트
```bash
npm test          # 단위 테스트 + RLS 테스트
npm run test:unit # 날짜·권한·ZIP·CSV·리포트·PIN·알림·ICS(표준 파서 icalendar 필요)·공유·피드 핸들러
npm run test:db   # PGlite 위에서 실제 마이그레이션을 실행해 RLS/RPC 검증
```
RLS 테스트 범위: 승인 전 접근 차단, 기본 접근 수준별 쓰기 권한, 비공개 환자, 환자별 명시 권한 우선, 가족 간 격리, 초대 코드 재발급, 복용 확인 위조·중복, 첨부 경로 규칙, 감사 로그 위조 차단, 관리자 보호(마지막 관리자·최대 2명), 휴지통 정리, 계정 삭제.
화면 확인용으로 `VITE_FAKE_BACKEND=1 npm run dev`(메모리 가짜 서버, 권한 모사 없음)를 제공하며 운영 빌드에는 포함되지 않습니다.

## 설계 결정 및 가정 (필요 시 조정)
- **기본 권한**: 승인 시 기본값은 "공동 편집"입니다. 보수적으로 운영하려면 승인 화면에서 "열람만" 또는 "환자별 지정만"을 선택하십시오. 환자 삭제·비공개 설정·코드 재발급·구성원 관리는 관리자 전용입니다.
- **초대 코드 저장**: 링크·QR 재표시를 위해 코드 평문을 관리자 전용 함수(`get_family_code`)로만 읽을 수 있는 비공개 스키마에 저장합니다. 코드만으로는 접근할 수 없고 관리자 승인이 필요합니다. 유출이 의심되면 즉시 재발급하십시오.
- **알림**: 푸시 서버 없이 이 기기에서 로컬로만 예약합니다. 사용자가 켠 기기에서, 선택한 환자에 한해, 기본값은 잠금 화면에 건강정보를 표시하지 않습니다. 웹은 앱이 열려 있는 동안만, 네이티브 앱은 앞으로 7일분을 예약합니다.
- **휴지통 자동 삭제**: 서버 스케줄러(pg_cron) 없이 관리자가 접속할 때 하루 1회 30일 경과 항목을 정리합니다.
- **내보내기 PDF**: 인쇄 대화상자의 "PDF로 저장"을 사용합니다(별도 PDF 라이브러리 미사용).

## 미구현·한계
- 음성 입력, 생체인증 잠금, 푸시 서버 알림, 오프라인 쓰기 대기열은 구현하지 않았습니다.
- 복용 확인(med_intakes) 조회는 최근 14일입니다(내보내기도 동일).
- 이전 Firebase 앱 데이터의 자동 이전은 하지 않았습니다.
- 마이그레이션 1~3번과 `calendar-feed` 함수는 실제 프로젝트에 적용·배포되어 점검했습니다. **`20261103000000_visit_details.sql`과 `ai-ocr` 함수는 PGlite·단위 테스트로만 검증했고 실제 프로젝트에는 아직 적용·배포하지 않았습니다**(커넥터 승인 창 미응답 → 관리자 수동 적용). 적용 전에도 앱은 기존 기능으로 동작하며 새 기능만 숨겨집니다.
- **AI 읽기는 실제 AI 서비스 호출을 이 환경에서 검증하지 못했습니다.** 요청·응답 형식은 각 서비스 공개 API 규격에 맞춰 작성하고 가짜 응답으로 테스트했으며, 실제 키로 '모델 목록 불러오기'와 '연결 테스트'를 먼저 확인하십시오. 모델 이름과 지원 기능은 서비스사가 바꿀 수 있습니다.
- 구글 캘린더의 구독 URL 수신, 카카오 SDK 공유 창, 모바일 앱의 외부 브라우저·공유창 동작은 실제 키·기기에서 확인하지 못했습니다.
- Android/iOS 실기기 동작, Storage 업로드, 실서버 알림 권한은 이 환경에서 검증하지 못했습니다.
- 개인정보 동의 문안(`PRIVACY.md`)은 초안이며 법률 검토가 필요합니다.
